## Overall Assessment

**Coverage completeness: ~30% of mandatory external auditor requirements are adequately covered by existing tasks.**

### Critical gaps (must fix before architectural refactoring):

1. **Coordinator concurrency accounting** (R-002/R-010/R-024): `_activeCount` decremented before physical work stops. `DrainQueue` does not check claimant-token liveness. Two independent audits confirm these defects at current HEAD. ICW-142's coordinator infrastructure exists but does not fix the specific bug mechanisms. **No task currently addresses this.**

2. **Pixelometer cache budget bypass** (R-004/R-014): `TryReadPixelValue` triggers untracked, unrecoverable tile generation. The generated pixel buffer exists outside `TileCacheBudget`'s accounting and can never be evicted. **No task currently addresses this.**

3. **Cooperative cancellation for native tile generation** (R-011): The mip factory only checks cancellation after expensive GDI+ work, making cancellation signals ineffective during the most expensive operations. **No task currently addresses this.**

4. **GDI+ concurrency in tile generation factories** (R-015): `ApplyDetailsWithGdiPlus` runs inside concurrent `Task.Run` delegates with no independent concurrency bound. During cancellation bursts, GDI+ operations can exceed DefaultMaxConcurrency by an unbounded amount. **No task currently addresses this.**

5. **Phase 0/1 sequencing** (R-020): The current implementation plan builds viewport-aware scheduling on top of a coordinator whose concurrency accounting is known to be wrong. The external auditor's Phase 0/1 items must precede the architectural refactoring. **No task currently captures this sequencing requirement.**

6. **Transactional regeneration** (R-005/R-013): A failed or canceled `RegenerateSceneAsync` can leave the app with partially-initialized state and no fallback to the previous scene. **No task currently addresses this.**

7. **Cache lease exactly-once release** (R-008/R-025): `ReleaseReservation` is a no-op diagnostic counter, not a real budget release. **No task currently fixes this specific mechanism.**

### Partially covered (existing tasks need scope expansion):

8. **Spatial index publish semantics** (R-007): ICW-060 exists but is Proposed with no implementation. Needs Phase 0 safety specification.

9. **Front/back buffer compositor synchronization** (R-006/R-019): ICW-021 exists but its ticket is a template with no concrete acceptance criteria.

10. **PixelCost mip accounting** (R-018/R-022/R-026): ICW-134 is broadly scoped but does not name the specific `_pixelCost` mip-0-only defect. Needs explicit test and fix scope.

11. **Settings validation unification** (R-016/R-017): ICW-030 and ICW-099 cover individual instances but not the structural pattern. Needs a task for unified validation functions.

12. **Settings/ViewModel lifecycle in Phase 1** (R-021): ICW-022 covers MainWindow decomposition but does not explicitly mandate settings-bug fixes as acceptance criteria.

13. **Migration sequencing strategy** (R-023): No task or ADR captures the concurrent-development policy during the 8-phase migration.

### Adequately covered:

14. **Stale-frame rejection** (R-012): ICW-078 (Done) covers render request epoch guarding. Verified by audit cross-reference.

15. **Generation input bounds** (partial of R-016): ICW-030 (Done) enforces `MaxObjectsPerTile = 256` in the generator. The `IsValid` gap is the remaining uncovered portion.
